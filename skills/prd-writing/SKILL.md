# PRD Writing
寫精簡、可被執行的 PRD：問題/使用者/解法/成功指標，綁可量測指標、守產品優先序。

## 何時用
把市場或接案訊號轉成需求、要決定做不做或排序時。

## 精簡 PRD 模板
1. **問題**：要解的痛點（一句話 + 為何現在）。
2. **使用者與情境**：誰、在什麼場景遇到。
3. **目前怎麼解 / 為何不夠**。
4. **提案解法**：MVP 範圍（明確列「做什麼、不做什麼」）。
5. **成功指標**：1–2 個可量測的（如：諮詢轉換率、每日省時、留存）。
6. **優先序理由**：為何符合「AgentOS 優先、YChatAgent 殿後」（見 [[company-plan]]）。
7. **相依/風險**：技術、成本、跨角色相依。

## 守則
- **每個提案必綁可量測成功指標**，否則不排入。
- 砍掉不符現階段優先序的東西，寧可範圍小而完整。
- 接案需求要思考：能不能沉澱成可複用的 AgentOS 能力（見 [[agentos-overview]]）。
- 寫完把可執行部分交 COO 排程、技術部分交 SA/Engineer。
